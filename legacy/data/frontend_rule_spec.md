# 前端可实现的提示规则（离线讨论版）

## 线上不使用的字段

`event_index / total_keys` 不进入前端规则，因为线上无法稳定获得总按键数。

## 离线审计结论

仅使用用户导出的真实标签时，共有 182 条确定标签（排除 53 条 `-1`）。当前最有区分力、且前端可实时计算的基线是：

```text
current_idle_s >= 30 秒
keys_30s < 5
```

在人工作为参考的标签上：

```text
触发 57 条
命中 41 条
误报 16 条
Precision 71.9%
Recall 67.2%
F1 69.5%
```

但是人工标签中存在“整道题统一标注”和长 idle 含义不一致的问题，因此这些指标只能作为离线基线，不能直接证明线上提示有效。

## 推荐的第一版候选条件

```text
current_idle_s >= 30 秒
keys_30s < 5
clipboard_ops_30s == 0
```

含义：最近 30 秒几乎没有按键，并排除复制粘贴主导的情况。它只用于产生候选事件，不等于立即强制弹窗。

## 前端状态机

一个 idle 周期只能产生一次候选事件，不能在 30、60、120 秒重复触发：

```text
ACTIVE
  -> OBSERVE：最近按键开始变少
  -> CANDIDATE：idle 达到 30 秒且 keys_30s < 5
  -> COOLDOWN：提示已展示、用户关闭、或用户继续输入
  -> ACTIVE：冷却结束且用户重新产生有效输入
```

## 必须增加的保护

1. 同一个 idle 周期只提示一次。
2. 同一 session 冷却 5–10 分钟，最多展示 1–2 次。
3. 用户继续输入、按下 Escape 或关闭提示后，立即取消提示并进入冷却。
4. Control/Meta+C/V 等剪贴板操作不作为卡顿依据。
5. 如果前端知道学生已经提交、正在运行代码、正在判题或已离开编辑器，则暂停候选逻辑。
6. 第一版采用非阻塞小提示或侧边提示，不使用必须处理的模态弹窗。
7. 记录触发特征、展示时间、关闭/点击、之后 30/60/120 秒的行为以及提交结果。

## 建议的提示文案

```text
需要一点提示吗？
[查看提示] [继续编写] [稍后再说]
```

## 上线顺序

1. Shadow mode：只记录规则触发，不向学生展示。
2. 内部灰度：仅对少量账号展示非阻塞提示。
3. 小规模 A/B：比较继续输入、提交率、AC率、关闭率和每 session 误打扰次数。
4. 有真实结果后再调整阈值或训练模型。

## 当前不能宣称

- 不能把 AI 补全标签上的 81.2% Precision 当作最终效果。
- 不能认为 idle 本身等于学生卡住。
- 不能根据当前离线数据证明弹窗提高了学习效果。
