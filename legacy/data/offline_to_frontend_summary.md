# 离线优化与前端落地总结

## 当前可信的离线基线

- 人工导出标签：235 条。
- 排除 `-1` 后：182 条确定标签，来自 39 个 session。
- 其中 15/39 个 session 的全部窗口被标成同一标签，存在整题批量标注偏差。
- 规则 `current_idle_s >= 30 && keys_30s < 5`：TP=41、FP=16、FN=20，Precision=71.9%、Recall=67.2%、F1=69.5%。
- 该结果用于筛选候选事件，不代表真实线上干预收益。

## 离线还应怎么优化

1. 重标边界窗口：重点标 idle 10–120 秒、keys_30s 0–10、复制粘贴、提交前后和少量修改窗口。
2. 禁止整题统一标注；每个窗口必须独立判断“此刻提示是否有帮助”。
3. 标签增加原因：`coding`、`thinking`、`checking`、`away`、`clipboard`、`stuck`、`unknown`。
4. 把“是否适合提示”和“提示后是否有效”分成两个标签，后者只能通过线上 shadow/A-B 获得。
5. 评估必须按 solution_id 分组，并同时报告窗口级指标、session级命中率和每 session 误提示数。
6. 采样应改成事件驱动：每次 idle 周期只生成一个 30 秒触发窗口，并加入活跃输入、提交前、判题后等对照窗口。

## 前端第一版规则

```text
idle >= 30 秒
过去 30 秒按键数 < 5
过去 30 秒没有 Ctrl/Meta+C/V 剪贴板行为
当前没有运行、提交、判题状态
本 idle 周期尚未提示
当前 session 不在冷却期
```

满足时只进入候选状态，展示非阻塞提示；不是强制模态弹窗。

## 前端保护

- 每个 idle 周期最多一次。
- 每个 session 最多 1–2 次，冷却 5–10 分钟。
- 继续输入、Escape、关闭提示后立即取消。
- 运行、提交、判题、切换页面时暂停。
- 提示应支持“查看提示 / 继续编写 / 稍后再说”。

## 必须记录的线上日志

- candidate_time、show_time、dismiss_time、reason。
- show/dismiss/help/continue/snooze 等用户动作。
- 触发前 5/10/30/60/120 秒特征。
- 提示后 30/60/120 秒是否继续输入、按键数、退格数。
- 下一次运行/提交时间、判题结果。
- session 内累计提示次数和冷却状态。
