# 离线实验阶段性报告

## 当前产物

- `causal_windows.csv`：183 条时刻级窗口，全部带唯一 `window_id`。
- `rebuild_windows.py`：从原始按键流重建窗口，只使用触发时刻之前的事件。
- `causal_eval.py`：可重复运行的规则评估和数据质量检查。

触发时间定义为：

```text

```

## 修正后规则结果

```text
规则                    Precision  Recall   F1
keys_30s < 5              76.0%    76.0%  76.0%
keys_60s < 20             85.9%    45.5%  59.5%
IDLE pause >= 30s         73.7%    60.3%  66.4%
```

## 必须如实说明的限制

`keys_30s < 5` 在修正后的 IDLE 窗口中仍然受到构造性影响：IDLE 窗口本身就是从一次超过 30 秒的停顿生成的，所以触发点前 30 秒按键很少是定义的一部分，而不是完全独立的预测验证。由此，旧实验中的 `F1=78.0%` 只能作为探索性结果，不能宣称为无偏泛化性能。

当前结果能支持的结论是：

1. 旧版触发点确实存在时间错位，已完成修正。
2. 时刻级数据已具备唯一标识，且没有未来事件泄漏。
3. 单纯比较 `idle` 或 `keys_30s` 仍不足以证明线上规则有效。
4. 下一步必须加入不由候选规则筛选的随机正常窗口和分层困难窗口，再进行留出验证。

## 汇报口径

> 我已经完成了第一轮真实 OJ 按键数据的规则探索，并发现原实验存在候选集选择偏差和触发时间错位。现在已按“停顿开始后达到阈值”的定义重建时刻级窗口数据，所有窗口具有唯一 ID，特征只使用触发前信息。修正后结果表明，`keys_30s<5` 在原候选集上的表现仍受构造性影响，因此暂不把它作为最终线上规则。下一步将补充随机正常窗口和困难窗口，采用按 session/学生分组的留出验证，重新确定规则或轻量模型。
